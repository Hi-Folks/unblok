# CLI and library operations

Start with `unblok --version` and `unblok --help`, then inspect the relevant command's `--help`. Use the installed command, or the invocation the user specifies. Command availability and options depend on the installed version. The [command reference](https://github.com/Hi-Folks/unblok/blob/main/docs/commands.md) describes the current source; verify it against that version.

Help is plain text, even when `--json` is also supplied. Use it to discover options and examples; use JSON for supported operation results.

Inspect the target space before adapting a recipe when its details are missing. Depending on the task, use `unblok space list --json`, `unblok story get --ref <id-or-full-slug> --space-id <id> --json`, `unblok component get <name-or-id> --space-id <id> --json`, `unblok language list --space-id <id> --json`, or `unblok workflow list --space-id <id> --json`. Inspect the relevant command's help for further options. Use the returned story content and component schema to choose actual components, fields and block identifiers; do not infer them from a generic example.

To discover stories, use `unblok story list --help` for filters such as `--starts-with`, `--search`, `--text-search`, `--component`, `--tag`, and publication state. The list is metadata; retrieve individual stories to inspect content.

To move one story, use `unblok story move --slug <current-full-slug> --folder <existing-folder-path> --space-id <id> --yes --json` after the user authorizes the change. Moving changes its full slug; use the returned `to` for subsequent operations. Retrying the original slug cannot identify the moved story and returns NOT_FOUND. This command does not move folders or create the target folder.

To organize root content, retrieve the bundled example with `unblok space setup example dimensions-country-setup`. It ensures root folders and uses `stories.organize_root` to move other root stories and folders into `global`, while preserving the named country folders. The sample app ID is confirmed for EU; verify it for the target region. It also creates an independent draft root `site-config` copy; adapt or remove that step if not applicable. Each apply selects current root entries, including ones added since a previous run. Plan cannot enumerate the entries; inspect the space and obtain authorization before apply. Moving content changes paths. See the [country setup recipe](https://github.com/Hi-Folks/unblok/blob/main/docs/recipes/dimensions-country-setup.md).

For structured content queries, inspect the component schema and story content first, then use repeatable `--field 'field:operator:value'`, for example `unblok story list --field 'category:in:news,events' --field 'featured:is:true' --space-id <id> --json`. Filters are combined with AND; comma-separated values supply alternatives where the operator supports them. Use `in_array` for any matching array member, `all_in_array` for all, `like` with quoted `*` wildcards for text, and `gt_date`/`lt_date` with `YYYY-MM-DD HH:MM`. Dotted paths target nested content (for example `seo.description` or `body.0.name`). Do not invent field names, use default story properties as content fields, use `any_in_array`, or assume OR grouping is supported. The [field filter reference](https://github.com/Hi-Folks/unblok/blob/main/docs/commands.md#content-field-filters) documents operators; the installed command's help is version-specific. In the library, pass `fieldFilters: [{ field, operator, value }]` to `listStories`.

Use `unblok story compare-languages --ref <story-id-or-full-slug> --language <space-language-code> --json` to compare stored field-level values for fields marked translatable in the component schema. Repeat `--language` for multiple configured additional languages. Missing stored values may use a fallback; equality does not determine translation quality. This does not compare separate folder-level stories.

For Dimensions folder variants, use `unblok story compare-dimensions --ref global/home --space-id <id> --json` to inspect all configured folders except the source folder. Repeat `--folder` to select particular root folders. This follows linked story alternates, not similar slugs; `missing` means no linked alternate was returned. The result compares raw draft content, including block IDs and arrays by position, and does not judge translation quality. Missing alternate metadata results in an error. Comparison of linked variants and a changed hero field has been exercised in a test space.

Discover configured folders with `unblok dimensions list --space-id <id> --json`. With authorization, create a linked variant using `unblok story create-variant --ref <story-id-or-full-slug> --folder <configured-root-folder> --space-id <id> --yes --json`. It requires an existing source group ID, preserves existing linked variants, and does not translate or publish. Storyblok may create intermediate folders and preserve the source path. YAML supports `stories.create_variants` as in `examples/features/setup-dimension-variants.yaml`. Do not assume a failed or unconfirmed duplicate made no changes; inspect the target before retrying. The updated request has not been verified live.

To request a Dimensions merge, use `unblok story merge --source <id-or-full-slug> --target <id-or-full-slug> --space-id <id> --yes --json` only when authorized. The target is modified. `submitted` confirms request acceptance, not completion; `queued` indicates a background task. Inspect the target before reporting completion or retrying. The merge request has not been verified live.

To synchronize selected fields between existing blocks, use `unblok story sync-block --source <story> --target <story> --component <name> --field <field> --plan --space-id <id> --json`; repeat `--field` as needed. Inspect the component schema and content to select real fields. Use `--source-uid` or `--target-uid` if a component is repeated. After authorization and review, rerun with `--yes` instead of `--plan`; it recomputes the plan and saves a draft, preserving other target fields. Each field is copied in full. YAML supports `stories.sync_blocks`; YAML plan is local and does not preview live values. Use JSON results and report ambiguous, missing, concurrent-change, or unconfirmed-write failures accurately. See the [comparison and synchronization guide](https://github.com/Hi-Folks/unblok/blob/main/docs/recipes/dimensions-compare-and-sync.md); check the installed command's help for version-specific options.

When available in the installed version, retrieve the matching YAML locally with `unblok space setup example dimensions-sync-field`; its inputs select source, target, component and field. The YAML performs the synchronization; compare linked stories separately before choosing what to copy.

To update every matching component within one story, inspect the component schema, then use `unblok story update-matching-blocks --ref <story> --component <name> --where 'field=value' --set 'field=value' --plan --space-id <id> --json`. The CLI uses exact string equality and string replacements; YAML and the library support non-string values. Review the matched paths, UIDs and changes. Apply with `--yes` only when authorized. It saves a draft and doesn't replace nested component blocks. YAML uses `stories.update_matching_blocks`; its local plan does not inspect live matches.

Use `unblok story versions --ref <id-or-full-slug> --json` to inspect history metadata, then `unblok story compare-versions --ref <id-or-full-slug> --from <version-id> --to <version-id> --json` to compare stored content. The current endpoint excludes versions created on or before August 28, 2024. Comparison fetches paginated history with content and compares arrays by index, so moved blocks can appear as several changes.

For the latest change against the current draft, use `unblok story compare-versions --ref <id-or-full-slug> --previous --json`. The command identifies preceding non-release history using timestamps and whether the newest stored content matches the draft; inspect `from` and `selection` in the result. It includes workflow-stage snapshots, which may have identical content, and fails when the relevant order cannot be determined. It does not compare unsaved editor state.

Prefer `--json` when the relevant command supports it. Inspect the exit status and both streams: a failure can include a partial-results report on stdout and a JSON error on stderr. Do not claim that a queued background task has completed. Only execute changes the user has authorized, respecting any instructions about who runs commands.

For application or integration code, consult the [library guide](https://github.com/Hi-Folks/unblok/blob/main/docs/library.md) for exports, arguments, errors, and return values. The library takes credentials through application configuration; do not embed or print tokens. Use the installed library's version and types as the final authority.
